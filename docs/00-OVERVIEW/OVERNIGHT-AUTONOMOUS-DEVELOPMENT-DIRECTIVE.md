## 1.1 自主开发原则

本任务采用高度自主模式。

1. 不要等待用户提供下一步任务。
2. 不要每完成一个功能就询问用户是否继续。
3. 不要要求用户为普通技术选择做决定。
4. 不要将任务停留在调研、分析和方案阶段。
5. 不要只输出计划而不实际写代码。
6. 不要因为某个任务受阻而停止整个项目。
7. 不要为了完成任务而降低质量。
8. 不要只追求功能数量，必须关注最终体验。
9. 不要为了技术炫酷而引入不必要的复杂度。
10. 不要将没有真实运行的功能标记为完成。

遇到问题时，按照以下规则处理：

- 能自主解决：立即解决。
- 有多个合理方案：研究后选择最合适的方案。
- 某个技术路线存在风险：先建立小型验证原型。
- 某个外部服务不可用：研究替代方案。
- 需要账号登录：记录下来，继续其他工作。
- 需要付费：禁止擅自购买，研究免费替代方案。
- 需要用户授权：记录到待处理清单，继续其他任务。
- 遇到技术阻塞：记录原因、尝试替代实现，不允许无限卡在一个问题上。

除涉及付费、不可逆操作、法律授权及敏感权限外，普通研发决策均由你自主完成。

# PART 02 — 项目愿景与产品定位

## 2.1 产品名称

WORLD EXPLORER

中文名称：世界探索计划

英文标语：

Explore the World. Discover Its Stories.

## 2.2 产品定位

WORLD EXPLORER 是一个融合：

- 3D 全球地理探索
- 世界文化与文明百科
- 历史与时间旅行
- 全球旅行目的地
- 世界奇观与自然探索
- 电影及影视取景地
- 沉浸式数字地球
- 个人探索与旅行记录

的交互式全球探索平台。

它不是普通地图产品，也不是传统旅游攻略网站。

我们希望用户进入这个平台后，产生一种感觉：

**我正在通过一个数字地球，探索真实世界的每一个角落，以及隐藏在这些地方背后的故事。**

## 2.3 产品体验目标

用户可以：

1. 从太空观察完整地球。
2. 自由旋转、缩放和探索地球。
3. 选择任意国家。
4. 进入国家，探索城市。
5. 进入城市，发现著名景点。
6. 点击景点，镜头自动飞向目的地。
7. 查看地点背后的历史、文化、人物和事件。
8. 发现世界遗产、自然奇观和神秘地点。
9. 查看电影中的经典取景地。
10. 创建自己的旅行路线。
11. 收藏喜欢的地点。
12. 记录去过的地方和未来想去的地方。
13. 通过历史资料了解同一个地点在不同时代的变化。

整个体验应当具有连贯性。

从太空到国家、城市、景点，再到内容档案，不能像打开多个互不相关的网页。

| 类型检查 | TypeScript strict |

## 5.2 引擎职责边界

CesiumJS 是地球和地理空间系统的核心。

负责：

- 地球。
- 地理坐标。
- 地形。
- 相机。
- 国家边界。
- 地理数据。
- 地理实体。
- 地理图层。
- 地球级场景渲染。

Three.js 只负责确实需要独立 3D 场景的部分。

例如：

- 特殊空间装饰。
- 独立 3D 展示场景。
- 特殊粒子效果。
- 特殊模型动画。

不要同时创建两个重复的地球渲染系统。

不要让业务组件直接操作 Cesium 内部对象。

## 5.3 建立独立地球运行时

设计 WorldEngine 接口。

建议包含：

```ts
interface WorldEngine {
  initialize(): Promise<void>;

  flyTo(
    longitude: number,
    latitude: number,
    height: number
  ): Promise<void>;

  setLayerVisibility(
    layerId: string,
    visible: boolean
  ): void;

  setDayNightMode(enabled: boolean): void;

  setTerrainMode(mode: string): void;

  destroy(): void;
}
```

根据实际实现调整接口。

业务层只调用接口，不直接管理 Viewer。

这样未来更换地球引擎时，不需要推翻整个产品。

## 5.4 重要架构原则

建立六层架构：

1. Experience Layer：页面、导航、搜索、面板。
2. Design System：设计令牌、组件、动效。
3. Domain Layer：国家、城市、景点、故事、路线。
4. 3D Runtime：Cesium、相机、地球、渲染。
5. Data & Assets：JSON、GeoJSON、图片、模型。
6. Dev Infrastructure：测试、构建、Git、文档。

必须保持各层职责清晰。

# PART 07 — Motion System 与交互体系

3D 地球最大的价值之一就是镜头和空间交互。

因此必须认真设计动画系统。

## 7.1 动画职责

- Cesium Camera：地理相机。
- GSAP：复杂动画编排和 UI 联动。
- Three.js AnimationMixer：独立模型动画。
- CSS：简单微交互。
- Vue Transition：组件进入和离开。

禁止多个系统同时控制同一个动画状态。

## 7.2 核心交互

用户点击一个景点：

1. 景点标记高亮。
2. 其他无关标记适当淡出。
3. 地球转向目标位置。
4. 镜头开始自然靠近。
5. 目标区域逐渐清晰。
6. 详情面板展开。
7. 地点图片与介绍逐步出现。
8. 用户可以继续探索周边。

整个过程应当连续自然。

不要突然跳转。

不要出现镜头飞行和面板动画互相打架。

## 7.3 相机控制权

必须明确：

- 程序动画何时拥有控制权。
- 用户手动拖动时如何处理动画。
- 连续点击多个地点时如何取消旧动画。
- 用户是否可以随时中断飞行。
- 面板滚动是否会误触地球缩放。
- 键盘操作如何控制视角。
- 移动端触控如何映射。

用户的主动操作优先级应高于自动播放动画。

## 7.4 必须支持

- Hover。
- Click。
- Double Click。
- Drag。
- Scroll。
- Zoom。
- Touch。
- Keyboard。
- Loading。
- Error。
- Empty State。
- Transition。
- Reduced Motion。

必须支持 prefers-reduced-motion。

# PART 08 — 全球数据与资产系统

这是决定项目能否长期发展的关键。

不能只有技术，没有内容。

## 8.1 数据来源

优先研究：

| 来源 | 用途 | 主要注意事项 |
|---|---|---|
| Natural Earth | 全球国家边界、海岸线 | Public Domain |
| Wikidata | 地点、人物、历史关联 | CC0 |
| Wikimedia Commons | 真实图片 | 逐张审核许可 |
| OpenStreetMap | POI、道路、建筑 | ODbL |
| GeoNames | 城市和地名 | CC BY 条款 |
| Copernicus DEM | 全球高程 | 核对具体许可 |
| Overture Maps | 建筑和地点数据 | 核对许可 |
| UNESCO | 世界遗产资料 | 内容和图片权利分别核查 |
| Poly Haven | 环境贴图和 3D 资源 | 核对资产许可 |
| ambientCG | PBR 材质 | 核对具体许可 |

这些来源不是可以不加审核地任意使用。

每个数据源都必须记录：

- 官方网址。
- 许可协议。
- 是否允许商业使用。
- 是否允许修改。
- 是否允许再分发。
- 是否需要署名。
- 是否有服务限制。
- 最后核验时间。

## 8.2 数据采集策略

采用：

发现 → 下载 → 标准化 → 去重 → 质量审核 → 许可审核 → 分级 → 静态发布。

优先本地化和静态化。

不要让前端每次打开地点都请求外部 API。

不要把全球所有数据一次性塞进首屏。

## 8.3 统一数据模型

建议：

```text

├── countries/
├── cities/
├── destinations/
├── stories/
├── routes/
├── collections/
├── media/
└── manifests/
```

每个实体必须有稳定 ID。

尽可能关联：

- Wikidata QID。
- OSM ID。
- GeoNames ID。

每条记录应具备：

- id。
- name。
- nameEn。
- aliases。
- type。
- countryId。
- cityId。
- longitude。
- latitude。
- description。
- contentRefs。
- mediaRefs。
- tags。
- sources。
- license。
- verificationStatus。
- qualityLevel。
- updatedAt。

根据不同实体扩展字段。

## 8.4 图片与模型管理

每个图片或模型必须记录：

- 资源名称。
- 来源。
- 作者。
- 原始链接。
- 许可证。
- 署名要求。
- 文件格式。
- 文件尺寸。
- 是否允许商业使用。
- 是否允许修改。
- 是否允许再分发。
- 对应地点。
- 核验日期。

优先使用 GLB / GLTF。

不要使用版权不清楚的 3D 模型。

不要只因为一个模型看起来漂亮就直接加入。

## 8.5 内容质量分级

建立：

- S 级：完整档案、优质图片、准确资料、多维度故事。
- A 级：资料较完整，图片和来源清楚。
- B 级：基础信息完整，部分内容待补充。

第一阶段优先建设 100 个高质量代表性地点。

之后逐步扩展至：

1000 → 10000 → 更大规模。

宁可少而精，也不要用大量低质量内容充数。

# PART 09 — 成本控制与服务使用红线

本项目原则：

**尽可能零成本，只有在必要且经过用户授权时才考虑付费。**

## 9.1 禁止擅自付费

不得：

- 购买 API。
- 开通付费地图服务。
- 购买模型。
- 购买图片。
- 开通付费服务器。
- 擅自绑定银行卡。
- 使用存在隐含费用的服务。
- 为了方便而引入收费 SaaS。

## 9.2 免费方案优先

优先：

- 静态数据。
- 开源引擎。
- 本地缓存。
- IndexedDB。
- GitHub Pages。
- 开放数据。
- 免费且许可明确的图片和模型。
- 自托管资源。
- 按需加载。

## 9.3 特别注意

CesiumJS 开源免费不代表 Cesium ion 所有服务都无限免费。

Google Photorealistic 3D Tiles 不作为默认方案。

OpenStreetMap 公共瓦片服务不能当成无限制免费 CDN。

公共数据接口不能被当成无限免费数据库。

任何有配额、计费或服务条款约束的资源，都必须单独研究。
