# PART 03 — P0：引擎稳定性与资源生命周期

这是整个阶段最优先的工作。

## 3.1 修复异步初始化与销毁竞态

重点审查：

- src/views/ExploreView.vue
- src/engine/world-engine.ts
- src/engine/imagery-layers.ts
- src/engine/countries-layer.ts
- src/engine/markers-layer.ts

目前 WorldEngine.initialize() 是异步初始化流程。

其中包括：

- Viewer 创建
- 影像加载
- 国家 GeoJSON 加载
- 标记创建
- 相机控制器初始化
- 事件处理器创建

重点检查以下情况：

场景 A：

用户进入页面，初始化还没有结束，就离开页面。

场景 B：

用户快速刷新或重新进入页面。

场景 C：

影像加载过程中发生异常。

场景 D：

国家 GeoJSON 加载失败。

场景 E：

初始化过程中调用 destroy()。

必须确保：

- 不会重复创建 Viewer。
- 不会在组件销毁后继续创建资源。
- 不会留下孤立的 Cesium Viewer。
- 不会重复注册事件。
- 不会留下 RAF、GSAP、事件监听器。
- 不会在已经销毁的 Viewer 上继续执行操作。
- 初始化失败后可以安全重试。

建议采用明确的生命周期状态：

idle → initializing → ready → destroying → destroyed

可以使用 AbortController、初始化序列标识或其他合理方案。

但必须真正解决竞态，不能只添加一个布尔变量掩盖问题。

## 3.2 修复 Vue 异步 Watch 生命周期

重点检查 ExploreView.vue。

目前部分 watch 在 onMounted 的异步流程中创建。

需要验证这些 watcher 是否能够随组件正常停止。

要求：

- 明确管理 watcher 生命周期。
- 组件卸载后不再触发引擎调用。
- 初始化失败时能够正确清理。
- 不允许页面反复进入后出现重复监听。

## 3.3 修复 Cesium Credit 和资源署名

重点检查：

src/styles/base.css

目前存在全局隐藏：

.cesium-widget-credits
.cesium-credit-lightbox-overlay

这可能导致底图、影像或其他数据源要求的署名无法正常展示。

必须重新审查。

要求：

- 不得为了界面整洁而隐藏必须展示的版权署名。
- 核实 CesiumJS、NASA GIBS 及未来其他数据源的署名要求。
- 设计与 WORLD EXPLORER 视觉风格统一的来源展示区域。
- 不能将应用内资料来源页面简单等同于运行时数据提供方的署名义务。
- 保留必要的第三方许可证和版权声明。

如果确实需要隐藏 Cesium 默认 UI，必须提供符合相关许可要求的替代展示方式。

## 3.4 引擎异常恢复

建立统一的错误处理策略。

覆盖：

- WebGL 初始化失败。
- 纹理加载失败。
- GeoJSON 加载失败。
- 瓦片加载失败。
- 浏览器资源不足。
- 网络中断。
- Viewer 意外销毁。

用户应该看到清晰、友好的错误提示，而不是无响应的黑屏。

## 3.5 验收标准

- 连续进入和退出场景不残留 Viewer。
- 初始化中途退出不会出现资源泄漏。
- 初始化失败后能够重新初始化。
- 控制台不存在未处理异常。
- 事件监听和图层资源可以完整释放。

# PART 04 — P1：地球视觉系统升级

本阶段需要真正提升地球的视觉表现。

不是简单增加几个滤镜。

目标：

让 WORLD EXPLORER 的地球成为产品最有辨识度的核心体验。

## 4.1 逐像素昼夜混合

当前：

ImageryLayersController 使用相机与日下点角距控制整层夜间贴图透明度。

这只是近似方案。

本阶段研究并实现更准确的昼夜过渡。

重点研究：

- Cesium Globe Surface Shader
- Custom Shader
- Globe 材质能力
- 日照方向计算
- 地球固定坐标与惯性坐标变换
- 太阳位置计算
- 晨昏线过渡
- 城市夜间灯光遮罩

目标：

1. 白天区域自然显示日间贴图。
2. 夜间区域显示城市灯光。
3. 晨昏线有自然的柔和过渡。
4. 夜灯不能覆盖白天区域。
5. 时间变化时昼夜边界能够连续移动。
6. 支持实时、永昼、永夜三种模式。
7. 不影响正常地球旋转和相机飞行。

注意：

不要直接修改 Cesium 内部不稳定 API 而不做版本验证。

优先研究当前锁定 Cesium 版本的官方能力。

如果自定义 Shader 的稳定性和维护成本过高，可以先完成一个经过验证的渐进式方案，并记录技术限制。

## 4.2 城市灯光升级

研究 NASA Black Marble 夜间灯光资源。

目标：

- 夜间城市灯光更加清晰。
- 城市密集区域有自然的光点分布。
- 不出现大面积不合理的发光。
- 亮度与昼夜模式匹配。
- 远景不过度刺眼。

禁止简单叠加大量随机发光点来伪造城市灯光。

## 4.3 星空背景

目前使用 Cesium 内置星空资源。

研究是否可以改善：

- 银河背景。
- 星点密度。
- 星体分布。
- 空间纵深感。
- 深空背景层次。

优先使用许可明确、可离线保存的资源。

不要使用未经许可的天文摄影图片。

如果当前内置星空已经满足质量要求，不必为了更换而更换。

## 4.4 云层

研究增加独立云层的可行性。

优先考虑：

- 许可清晰的 NASA 云层贴图。
- 本地静态资源。
- 轻量级球面云层。
- 可关闭的云层图层。

要求：

- 云层能够独立开关。
- 云层与地球表面具有正确的空间关系。
- 不影响相机控制。
- 不明显增加 GPU 负担。
- 支持低性能模式。

云层如果影响性能，优先提供质量等级控制，而不是强制开启。

## 4.5 大气效果

进一步优化：

- 大气边缘光。
- 地球轮廓。
- 地平线效果。
- 深空与地球之间的视觉关系。

整体风格应该克制、真实、精致。

避免过度蓝色光晕。

# PART 05 — P1：地理标记与探索交互升级

目前目的地标记具备点和标签两级显示，但还没有真正的屏幕空间防碰撞系统。

需要升级。

- 标签优先级
- 距离分级

目标：

同一视野中不允许大量标签互相遮挡。

优先级建议：

1. 当前选中地点。

4. 重要世界遗产。
5. 普通目的地。

允许低优先级标签在密集区域隐藏。

不要为了显示全部标签而牺牲可读性。

## 5.2 标记视觉升级

研究更精致的地理标记：

- 核心圆点。
- 外环。
- 轻量呼吸动画。
- 选中状态。
- Hover 状态。
- 距离缩放。
- 分类识别。
- 高亮状态。

要求：

- 视觉简洁。
- 不遮挡地图。
- 不出现大面积霓虹光。
- 选中状态明确。
- 不同类别可以识别。
- 与 Design System 统一。

不要让每个地点都使用完全相同的视觉权重。

## 5.3 国家选择体验

优化：

- 国家边界显示。
- Hover 状态。
- 点击反馈。
- 国家高亮。
- 国家中心计算。
- 国家飞行镜头。
- 国家档案面板。

特别检查跨日期变更和多国边界等异常数据。

国家中心计算不能简单依赖经纬度算术平均。

对于跨越国际日期变更线的国家，应采用正确的地理中心估算或经过验证的中心点数据。

## 5.4 相机控制

继续保持：

Cesium Camera 是唯一的地理相机控制入口。

GSAP 只负责 UI 动画，不得与 Cesium Camera 争夺控制权。

重点改善：

- 飞行速度。
- 镜头缓动。
- 近地表抵达体验。
- 连续目标切换。
- 飞行取消。
- 手动拖动中断。
- 自动旋转恢复。
- 极区视角。
- 最小缩放距离。
- 不合理的地下视角。

同时修复相机交互检测和文档之间的不一致。

例如：

简单点击与真正拖动是否都应该关闭自动旋转？

应当通过实际交互体验决定。

# PART 06 — P1：性能与加载架构

## 6.1 Cesium 代码拆分

目前 package.json 和构建配置中：

- Cesium 是核心依赖。
- Vite chunkSizeWarningLimit 设置为 4500KB。
- V0.1 报告记录主 chunk 约 4.37MB。

不能通过不断放大 chunkSizeWarningLimit 解决问题。

必须研究真正的代码拆分。

重点：

- 路由懒加载。
- Cesium 独立 chunk。
- 3D 场景按需初始化。
- 非核心组件按需加载。
- 设计实验页面与主场景分离。
- 第三方依赖分包。
- 图片延迟加载。
- 数据分片加载。

注意：

Cesium 的 Workers、Assets、Widgets 和静态资源复制配置必须保持正确。

不能因为拆包导致 Worker 路径错误。

## 6.2 首屏优化

优化：

- 初始 HTML。
- JS 加载。
- 地球初始化。
- 贴图加载。
- 数据加载。
- UI 首次出现。
- 可交互时间。

可以研究加载顺序：

第一阶段：展示基础界面与加载状态。

第二阶段：加载必要数据。

第三阶段：创建地球引擎。

第四阶段：加载主要地理图层。

第五阶段：逐步加载非核心资源。

不要让所有内容都阻塞首屏。

## 6.3 渲染性能

研究：

- resolutionScale。
- MSAA。
- FXAA。
- 图层数量。
- Entity 数量。
- Label 数量。
- 影像瓦片加载。
- requestRenderMode。
- GPU 负载。

低性能模式必须有实际效果，而不是只修改一个 UI 开关。

根据测试结果建立：

- High Quality
- Balanced
- Performance

三个质量策略。

不要盲目设置固定 FPS 目标而忽略设备差异。

## 6.4 性能预算

建立性能记录表。

至少记录：

- 冷启动时间。
- 首次可交互时间。
- 主 JS 文件体积。
- Gzip 体积。
- 地球初始化耗时。
- FPS。
- JS Heap。
- GPU 相关异常。
- 资源重复加载情况。

保留 V0.1 的数据作为对比基线。

# PART 07 — P1：数据系统与本地存储

WORLD EXPLORER 的长期价值不只是地球视觉，而是丰富、可信的世界数据。

本阶段先把现有数据体系做扎实。

## 7.1 运行时数据校验

当前 data-service.ts 使用泛型和类型断言解析 JSON。

TypeScript 类型不会自动验证运行时 JSON。

必须建立真实的数据结构校验。

研究适合的方案：

- Zod
- Valibot
- 自定义轻量校验器

先比较体积、许可、维护成本和项目实际需求。

不允许为了一个简单验证功能引入过重的依赖。

必须验证：

- 国家 ID。
- 城市 ID。
- 目的地 ID。
- 经纬度范围。
- 国家关联关系。
- 分类枚举。
- 质量等级。
- 资料来源。
- 图片路径。
- 日期字段。
- 重复 ID。
- 缺失字段。

异常数据应该被明确报告。

不能静默显示错误数据。

## 7.2 数据质量体系

建立内容质量检查工具。

每条目的地至少检查：

- 中文名称。
- 英文名称。
- 坐标。
- 国家。
- 城市。
- 分类。
- 简介。
- 故事。
- 标签。
- 来源。
- 更新时间。
- 图片状态。

建立 S / A / B 三级内容质量标准。

S 级必须具备较完整、可信、可追溯的内容。

禁止单纯为了增加地点数量而批量制造低质量内容。

## 7.3 本地存储升级

重点审查：

- src/stores/my-world-store.ts
- src/services/storage-service.ts

目前采用 localStorage。

本阶段先实现安全的数据导入和导出。

要求：

1. 导入前验证数据结构。
2. 验证数据版本。
3. 检查目的地 ID 是否存在。
4. 拒绝非法数据。
5. 避免错误覆盖现有数据。
6. 提供导入预览。
7. 提供导入结果。
8. 支持失败回滚。
9. 支持完整 JSON 导出。
10. 不允许未知字段任意写入应用存储。

可以研究 Dexie / IndexedDB。

但只有在实际数据规模和功能需求证明必要时才迁移。

不要为了使用新技术而迁移。

## 7.4 数据离线能力

WORLD EXPLORER 应当尽量依赖本地资源。

继续强化：

- 本地 JSON。
- 本地 GeoJSON。
- 本地纹理。
- 本地照片。
- 资源缓存。
- 离线降级。

NASA GIBS 可以作为增强服务，但不能成为整个地球无法运行的单点依赖。

- 品牌标识。
- 导航层级。
- 模块入口。
- 搜索入口。
- MY WORLD 入口。
- 移动端导航。

目前多个规划中的导航入口只是 disabled 按钮。

必须明确区分：

- 已上线模块。
- 正在建设的模块。
- 暂未开放的模块。

不能让用户误以为按钮失效。

可以采用合理的预览或开发中提示，但不要制造大量无意义的禁用按钮。

## 8.3 左侧控制栏

优化：

- 图层控制。
- 昼夜模式。
- 自动旋转。
- 性能模式。
- 性能信息。

考虑将低频设置折叠到二级面板。

让主要探索操作更加突出。

## 8.4 目的地档案面板

重点优化：

- 头图。
- 标题。
- 地点信息。
- 坐标。
- 简介。
- 故事。
- 标签。
- 收藏操作。
- 资料来源。

让它更像高质量的数字博物馆和旅行杂志。

不要把所有信息都做成简单卡片。

## 8.5 搜索体验

重点优化：

- 搜索输入。
- 中英文搜索。
- 搜索结果分类。
- 键盘导航。
- 无结果状态。
- 加载状态。
- 搜索结果选择。
- 移动端输入体验。

必须修复搜索结果为空时的键盘索引边界情况。

支持合理的焦点管理。

## 8.6 动画系统

GSAP 继续作为主要动画编排工具。

但不要所有动画都使用 GSAP。

CSS 适合简单状态切换，GSAP 适合复杂时间线。

建立统一 Motion System。

重点：

- 面板出现。
- 搜索弹窗。
- 导航反馈。
- 标记状态。
- 国家选择。
- 地点选择。
- 内容切换。
- 加载状态。
- 页面转场。

所有动画都要尊重 prefers-reduced-motion。

避免过度弹跳和不必要的持续动画。

- Focus 状态。

- 图片替代文本。

- 焦点陷阱。
